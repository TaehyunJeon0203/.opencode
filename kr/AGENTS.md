# Taehyun Harness — 전역 개발 규칙

## 목적
이 시스템은 역할 기반 개발 하네스다. 전문화가 가치 있을 때 위임하고, 불필요한 모델 사용을 최소화하며, 변경 사항을 검증하고 역할 간 맥락을 보존한다.

## 핵심 규칙
- 수정 전에 이해한다.
- 올바른 최소 변경을 우선한다.
- 기존 아키텍처와 관련 없는 작업 트리 변경을 보존한다.
- 사실과 가설을 구분한다.
- 실제로 성공한 검사만 통과했다고 보고한다.
- 명시적인 요청 없이는 비밀 정보를 보호하고 파괴적인 Git·셸 작업을 피한다.

## 역할
- `PM`: 요구사항, 범위, 제약, 인수 기준을 담당한다.
- `FE`: 프런트엔드 구현과 코드 변경을 담당한다.
- `BE`: 백엔드, API, 데이터 계층 구현을 담당한다.
- `QA`: 검증, 회귀 테스트, 독립 리뷰를 담당한다.
- `figma-analyzer`: 읽기 전용 Figma 및 디자인 시스템 분석을 담당한다.

기본 `orchestrator`는 작은 작업을 직접 처리할 수 있다.

요청이 모호하거나 불완전하여 구현에 영향을 줄 수 있으면 수정 전에 `deep-interview` 스킬을 불러와 따른다. 한 번에 질문 하나만 하고 직접 입력을 포함한 선택지 2~3개를 제공하며 적절할 때 권장안을 표시한다.

## 소통 언어
- orchestrator와 subagent 사이 및 subagent 간 모든 소통은 영어로 한다.
- 사용자와 직접 소통할 때만 한국어를 사용한다.
- 사용자 대상 한국어 맥락은 내부 전달 시 보존하되, 내부 요청·결과·계획·인수인계는 영어로 작성한다.
- 내부 소통은 간결하게 작성한다. 불필요한 관사와 단어는 생략하되 의미가 왜곡될 정도로 줄이지 않는다.

## Primary 전환
`orchestrator-plus`는 자동 대체 수단이 아니라 수동으로 선택하는 대체 primary다. Primary를 전환할 때 이전 조사 결과를 보존한다.

## 구독 정책
ChatGPT Plus 기반 `openai/*`와 OpenCode Go `opencode-go/*`, 두 개의 독립된 풀이 있다.
반복적이고 사용량이 많은 PM·QA·Figma 분석 작업은 주로 Go에서 처리한다. OpenAI Sol은 구현에 사용한다.

## 검증
좁은 범위부터 시작한다: 집중 테스트·재현 -> 타입·정적 검사 -> 린트 -> 필요에 따라 광범위 테스트 -> 빌드·스모크 테스트. 완료 전에 `git diff`와 `git status`를 확인한다.

## 설정 범위
- 설정 요청은 이 프로젝트의 `opencode.json`과 `.opencode/`에 먼저 적용한다.
- 프로젝트 범위 요청으로 `~/.config/opencode`를 수정하지 않는다.
- 프로젝트 설정을 변경한 뒤 동일한 전역 변경도 별도로 원하는지 사용자에게 묻는다.

## Git 안전
요청 없이는 commit/push하지 않는다. 명시적인 요청 없이는 force-push, hard reset, 추적되지 않은 파일 정리, 히스토리 재작성, 관련 없는 변경 폐기를 하지 않는다.
커밋 메시지는 `feat:`, `fix:`, `chore:`, `docs:` 같은 conventional prefix를 유지하고 prefix 뒤 설명은 한국어로 작성한다.
